# 体验契约（UX Contract）

> 适用于 Claudian Plus 3.2.7 – 3.2.20。每个版本开工前读一遍；任何改动都不能破这些红线。
> 契约冲突时：先改本文档（记录原因），再改实现。

| # | 规则 | 一句话判定 |
| --- | --- | --- |
| 1 | 不静默失败 | 失败必有可见条目，含原因与一个可点的下一步 |
| 2 | 不丢工作 | 草稿/布局/位置/状态跨重载恢复；破坏性操作可撤销或需确认 |
| 3 | 不猜 | 能力边界在入口显式（禁用 + 原因），不是点了才报错 |
| 4 | 一条主路径 | 同一件事只有一个入口，其余入口指回主路径 |
| 5 | 说了算数 | 设置立即生效，或明示"下次生效" |
| 6 | 空状态有下一步 | 每个空视图给一个主操作 |
| 7 | 键盘可达 | Tab 到、Enter/Space 触发、Esc 退出、焦点可见 |
| 8 | 主题不站队 | 颜色/间距/圆角/字阶全部来自 token |
| 9 | 十语同权 | 用户可见文案全走字典 |
| 10 | 慢也有解释 | >1s 有骨架/进度，>10s 可取消 |

---

## 1. 不静默失败

- **为什么**：面板是长时间停留的工作区，一闪而过的浮层等于没有反馈；用户需要"刚才为什么失败"。
- **判定**：失败路径能回答三件事——发生了什么、为什么、现在能做什么。三件事缺一即不合格。
- **反例**：`new Notice('Failed to create tab')`（无原因、无下一步、无历史）。
- **正例**：`FeedbackBus.emit({ level: 'error', key: 'tab.create.failed', title: t('feedback.tabCreateFailed'), actions: [{ id: 'retry', label: t('common.retry'), run }] })`。
- **守卫**：chat 面禁止裸 `new Notice(`；错误路径必须有 `FeedbackEntry`。

## 2. 不丢工作

- **为什么**：用户写下的提示词、摆好的标签、读到的位置，都比插件本身重要。
- **判定**：重载、崩溃、切会话、关面板之后，草稿、标签顺序、阅读位置、折叠状态、GenUI 控件状态至少恢复其一且不互相污染。
- **反例**：未发送草稿只在内存；关闭标签直接丢弃后台任务状态。
- **正例**：`composerDraft` 防抖写入 tab layout，发送即清，旧版本读取时忽略未知字段。
- **守卫**：草稿 round-trip 单测；危险操作（删除会话、清空记忆、批量写入）必须有确认或撤销。

## 3. 不猜

- **为什么**：7 个 provider 能力不同，"点了才知道不支持"是最贵的交互。
- **判定**：任何依赖 provider 能力的功能，在入口处就能看到"可用/不可用/原因"。
- **反例**：点了 fork 才弹 `Fork is not supported by this provider.`
- **正例**：`ProviderCapabilities.supportsFork === false` → 菜单项禁用 + tooltip 说明。
- **守卫**：能力矩阵测试；feature 层不得硬编码 provider id。

## 4. 一条主路径

- **为什么**：功能面已经够大，同一件事两个入口会让人怀疑"是不是不一样"。
- **判定**：同一目标只有一个主入口；次要入口要么指向主入口，要么明确标注差异。
- **反例**：会话切换既有隐藏标签条、又有历史下拉、又有会话列表，三者行为不一致。
- **正例**：标签 chip 是主入口；会话列表的"在新标签打开"指向同一套标签操作。

## 5. 说了算数

- **为什么**：设置页是信任的源头，切换开关必须立刻有反应。
- **判定**：设置项要么立即生效并有可见反馈，要么明确写"下次会话生效"。
- **反例**：改了模型可见性，聊天里不刷新；改了语言，部分界面仍是旧语言。
- **正例**：设置变更 → 统一走 `settings` 订阅 → 相关面板重渲染 + 一条反馈。

## 6. 空状态有下一步

- **为什么**：空视图是新用户唯一能看到的"产品说明"。
- **判定**：每个空状态都有：一句解释 + 一个主操作按钮。
- **反例**：`No chat sessions yet`（无按钮、无解释）。
- **正例**：空会话列表 → "还没有会话" + 「开始第一个会话」按钮。

## 7. 键盘可达

- **为什么**：Obsidian 用户大量使用键盘；鼠标专用控件等于不可用。
- **判定**：Tab 能到、Enter/Space 能触发、Esc 能退出、焦点环可见；模态有焦点陷阱。
- **反例**：`div role="button"` 没有 keydown；工具条只能 hover 出现且进入后立即消失。
- **正例**：hover 显示 + 焦点进入保持可见；`aria-pressed` 同步。

## 8. 主题不站队

- **为什么**：Obsidian 主题生态庞大，硬编码颜色在第三方主题下必然破。
- **判定**：CSS 中不出现字面量颜色/圆角/间距/字号，一律 token；明暗与第三方主题下无"看不清"。
- **反例**：`border-radius: 6px`、`padding: 10px`、`#ef4444`。
- **正例**：`var(--claudian-plus-radius-sm)`、`var(--claudian-plus-ui-space-md)`、`var(--text-error)`。
- **守卫**：`style-tokens.test.ts`（颜色，全库）、`generative-ui-baseline.test.ts`（GenUI 几何）、`geometry-ratchet.test.ts`（3.2.10 起，全库只减不增）。

## 9. 十语同权

- **为什么**：对外承诺 10 个 locale，就不能让 8 种语言看英文。
- **判定**：用户可见字符串 100% 走 `t()`；10 语 key 集合与占位符一致。
- **反例**：`localeText('保存', 'Save')`（ja/ko/de/fr/es/ru/pt 全是英文）。
- **正例**：`t('settings.save')`，10 个 json 都有该 key。
- **守卫**：`copy-ratchet.test.ts`、`locale-parity.test.ts`、`locale-format.test.ts`。

## 10. 慢也有解释

- **为什么**：CLI 启动、模型思考、长工具链都可能慢；没有进度就是"卡死"。
- **判定**：>1s 的操作有骨架/进度/状态文案；>10s 可取消并保留已完成部分。
- **反例**：点了发送，界面静止 8 秒，无任何状态变化。
- **正例**：回合状态条 `preparing → streaming → waiting-tool`，带可取消按钮。
